# Version-to-version probes

Cheap checks that scope a Pandoc bump before any template is ported. Set `OLD` and `NEW` to the Pandoc binaries: the bundled one (`package/dist/bin/tools/<arch>/pandoc`, or `tools/pandoc.exe` on Windows) and the target release, downloaded from <https://github.com/jgm/pandoc/releases> into a scratch directory. Copy the bundled binary to scratch too, because Phase 2's `configure` replaces it and test triage needs it later. The commands are bash; on Windows, Git Bash runs them.

## Lua API

```bash
"$OLD" lua -e 'print(PANDOC_VERSION, PANDOC_API_VERSION)'
"$NEW" lua -e 'print(PANDOC_VERSION, PANDOC_API_VERSION)'
```

A changed `PANDOC_API_VERSION` means the AST types changed: review `doc/lua-filters.md` upstream and `src/resources/lua-types/`. When it is unchanged, the Lua types usually need no update, but still skim the `lua-filters.md` diff for new module functions.

## Formats and extensions

```bash
diff <("$OLD" --list-output-formats) <("$NEW" --list-output-formats)
diff <("$OLD" --list-input-formats)  <("$NEW" --list-input-formats)
diff <("$OLD" --list-extensions=markdown) <("$NEW" --list-extensions=markdown)
```

`src/core/pandoc/format-extension.ts` is regenerated by `quarto-bld update-pandoc` (`writeVariants`). It lists extensions only, so a new extension shows up in its `git diff` and a new format does not. A new format needs a separate decision on whether Quarto exposes it (`src/resources/schema/format-aliases.yml`, other schemas, format handlers); track that on its own.

## CLI options

```bash
diff <("$OLD" --help) <("$NEW" --help)
```

For every added, renamed or deprecated option, check `parseRenderFlags` in `src/command/render/flags.ts`. Deprecated aliases may now print Pandoc warnings through `quarto render`, and a new canonical form may not be detected by Quarto at all.

## Template diff

```bash
gh api --paginate "repos/jgm/pandoc/compare/$OLD_TAG...$NEW_TAG?per_page=100" \
  --jq '.files[]? | select(.filename | startswith("data/templates")) | .filename' | sort -u
```

Without `--paginate`, the compare API stops at 300 files and drops templates in a multi-release range. The list says which reference copies will change and therefore which Quarto templates need a port (map in `dev-docs/update-pandoc-checklist.md`).

## Writer probes

Render small inputs through both binaries for the formats Quarto wires to Pandoc writers whose output Quarto post-processes or snapshots: typst, latex, html, docx, markdown. For example:

```bash
printf -- 'a\n\n---\n\nb\n' | "$OLD" -t typst > old.typ
printf -- 'a\n\n---\n\nb\n' | "$NEW" -t typst > new.typ
diff old.typ new.typ
printf 'Text\n\n$$\nx = 1\n$$\n' | "$NEW" -f markdown -t markdown
```

Probe each changelog item that mentions a writer. A probe that shows no difference is not proof of no change: Quarto and the visual editor pass their own options and extensions. Confirm risky items with a `quarto render` of a real document on both versions.

## Changelog triage

Read the changelog sections for every release between old and new (<https://github.com/jgm/pandoc/blob/main/changelog.md>), not only the target. For each entry that touches a format Quarto supports, a template, YAML/metadata parsing, citeproc, or the CLI, decide one of:

- **No impact**, with the reason (format not used by Quarto, behavior already overridden).
- **Risk**: one work item with a minimal `.qmd` repro, rendered on old and new, with the observed difference. Its outcome is a fix, a test update with the upstream change named, or a changelog/release-note line.

Changes that alter existing documents without error (ids, numbering, layout, math rendering, metadata values) are the ones users report later. They need a repro even when the changelog marks them as improvements.
